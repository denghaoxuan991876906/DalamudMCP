**InvokeSafeIpc 方法（internal static）：**
- 返回类型：`SafeInvokePluginIpcResult`
- 参数：`IPluginIpcGateway gateway, Request request`
- 实现步骤：
  1. `ArgumentNullException.ThrowIfNull(gateway)` 和 `ArgumentNullException.ThrowIfNull(request)`
  2. `string pluginName = request.PluginName.Trim();`
  3. `string method = request.Method.Trim();`
  4. `string callgate = $"{pluginName}.MCP.{method}";`
   5. 进入 `try` 块，包裹步骤 5-9 的全部核心流程（如 `ParseArguments` 的 `JsonException` 等错误也会被捕获并转换为 `ipc_plugin_error`）：
   6. `ParseArguments(request.ArgumentsJson)` → 返回 `(object?[] arguments, Type[] argumentTypes)`
   7. `Type[] typeArguments = [.. argumentTypes, typeof(object)];`（返回类型固定为 object）
   8. 调用 `gateway.TryCreate(callgate, typeArguments, out IPluginCallGateSubscriber? subscriber)`：
      - 返回 false 或 subscriber is null → 返回 `SafeInvokePluginIpcResult` 且 `Success = false, Status = "ipc_missing"`
        - ErrorMessage: `$"No IPC subscriber found for callgate '{callgate}'."`
        - SummaryText: `$"IPC call failed: callgate '{callgate}' not found (ipc_missing)."`
   9. 检查 `!subscriber.HasFunction` → 返回 `SafeInvokePluginIpcResult` 且 `Status = "ipc_not_ready"`
      - ErrorMessage: `$"IPC function for callgate '{callgate}' is not registered yet."`
      - SummaryText: `$"IPC call failed: callgate '{callgate}' not ready (ipc_not_ready)."`
   10. 调用 `object? result = subscriber.InvokeFunc(arguments)` — 捕获以下异常：
      - 成功：`string returnJson = JsonSerializer.Serialize(result, typeof(object));` → Status = `"ipc_success"`, Success = true, ReturnValue = returnJson, ErrorMessage = null
        - SummaryText: `$"IPC '{callgate}' succeeded. Return value: {returnJson}."`
      - 捕获 `InvalidCastException ex` → Status = `"ipc_type_mismatch"`
        - ErrorMessage: `$"Type mismatch: {ex.Message}"`
        - SummaryText: `$"IPC call failed: type mismatch for callgate '{callgate}'."`
      - 捕获 `TargetInvocationException ex when (ex.InnerException is InvalidCastException)` → Status = `"ipc_type_mismatch"`
        - ErrorMessage: `$"Type mismatch: {ex.InnerException.Message}"`
        - SummaryText: `$"IPC call failed: type mismatch for callgate '{callgate}'."`
      - 捕获 `TargetInvocationException ex when (ex.InnerException is not null)` → Status = `"ipc_plugin_error"`
        - ErrorMessage: `ex.InnerException.Message`
        - SummaryText: `$"IPC call failed: plugin error for callgate '{callgate}'. {ex.InnerException.Message}"`
      - catch 块中还捕获 `Exception ex`（如 `JsonException`、`ArgumentException`、`NotSupportedException` 等）→ Status = `"ipc_plugin_error"`
        - ErrorMessage: `ex.Message`
        - SummaryText: `$"IPC call failed: error for callgate '{callgate}'. {ex.Message}"`

**ParseArguments 方法（private static）：**
- 返回类型：`(object?[] arguments, Type[] types)`
- 如果 `string.IsNullOrWhiteSpace(argumentsJson)` → 返回 `([], [])`
- 使用 `JsonDocument.Parse(argumentsJson)` 解析
- 验证根元素是 `JsonValueKind.Array`，否则抛出 `ArgumentException("arguments-json must be a JSON array.")`
- 遍历每个元素，调用 `ParseJsonElement` 获取 `(object? value, Type type)`
- 返回 arguments 数组和 types 数组

**ParseJsonElement 方法（private static）：**
- 返回类型：`(object? value, Type type)`
- 使用 switch 表达式基于 `element.ValueKind`：
  - `JsonValueKind.True` → `(true, typeof(bool))`
  - `JsonValueKind.False` → `(false, typeof(bool))`
  - `JsonValueKind.Number when element.TryGetInt32(out int i)` → `(i, typeof(int))`
  - `JsonValueKind.Number` → `(element.GetDouble(), typeof(double))`
  - `JsonValueKind.String` → `(element.GetString()!, typeof(string))`
  - `JsonValueKind.Object or JsonValueKind.Array` → `(element.GetRawText(), typeof(string))` — JSON 字符串信封
  - `JsonValueKind.Null` → `(null!, typeof(object))`
  - `_` → throw `ArgumentException($"Unsupported JSON value kind: {element.ValueKind}")`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AI MCP 客户端 → CLI 桥接 | 不可信输入（plugin-name、method、arguments-json）从 AI 端进入 CLI 进程 |
| CLI 桥接 → Plugin 命名管道 | 序列化操作通过本地命名管道传输（本地进程间） |
| Plugin → Dalamud IPC | 安全操作通过 IPluginIpcGateway 调用目标插件的 IPC CallGate |
| Dalamud IPC → 目标插件 | 跨插件调用边界（同一进程内） |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Spoofing | MCP 客户端身份 | accept | MCP 服务在本地运行，无身份验证需求（v1.1 范围） |
| T-14-02 | Tampering | PluginName/Method 参数 | mitigate | 输入验证：`ArgumentException.ThrowIfNullOrWhiteSpace` 拒绝空字符串；只有已安装插件的 IPC CallGate 可被查找 |
| T-14-03 | Repudiation | IPC 调用审计日志 | accept | 仅本地运行，不产生审计日志 |
| T-14-04 | Information Disclosure | IPC 返回值泄露到 AI | accept | IPC 返回值来自用户已安装的插件；MCP 本地运行，无网络暴露 |
| T-14-05 | Denial of Service | 恶意/超大 JSON arguments-json | mitigate | `JsonDocument.Parse` 内置深度/大小限制；try-catch 将所有解析异常转为 `ipc_plugin_error` 状态码，不会崩溃 |
| T-14-06 | Elevation of Privilege | 通过 IPC 执行任意代码 | accept | IPC 调用仅能执行目标插件已注册的 CallGate 函数；反射调用 `MethodInfo.Invoke()` 由 .NET 类型安全机制保护；无法执行未安装插件的方法 |

**注意：** `plugin.ipc` 被归类为 unsafe 操作——与 `plugin.reload` 和 `command.slash` 同级。它受 PluginOperationExposurePolicy 的 UI 安全开关控制，用户可在 UI 中手动启用/禁用 unsafe 操作。
