```csharp
private readonly Func<Request, CancellationToken, ValueTask<SlashCommandResult>> executor;

[SupportedOSPlatform("windows")]
public SlashCommandOperation(IFramework framework, ICommandManager commandManager)
{
    ArgumentNullException.ThrowIfNull(framework);
    ArgumentNullException.ThrowIfNull(commandManager);
    executor = CreateDalamudExecutor(framework, commandManager);
}

internal SlashCommandOperation(Func<Request, CancellationToken, ValueTask<SlashCommandResult>> executor)
{
    this.executor = executor ?? throw new ArgumentNullException(nameof(executor));
}
```

**ExecuteAsync：**

```csharp
public ValueTask<SlashCommandResult> ExecuteAsync(Request request, OperationContext context)
{
    ArgumentNullException.ThrowIfNull(request);
    ArgumentNullException.ThrowIfNull(context);
```

**CreateDalamudExecutor 静态方法（核心逻辑）：**
1. 输入验证（per D-01/D-02）：
   - 若 `!request.Command.StartsWith("/", StringComparison.Ordinal)` → 返回 `SlashCommandResult(Command: request.Command, Success: false, Status: "validation_failed", SummaryText: "命令必须以 '/' 开头。")`
   - 若 `request.Command.Length > 256` → 返回 `SlashCommandResult(Command: request.Command, Success: false, Status: "validation_failed", SummaryText: "命令长度超过 256 字符上限。")`
   - 不 Trim 命令字符串，不检查额外字符
2. 线程编排与命令发送：
   ```csharp
   try
   {
       if (framework.IsInFrameworkUpdateThread)
       {
           commandManager.ProcessCommand(request.Command);
       }
       else
       {
           await framework.RunOnFrameworkThread(() =>
           {
               commandManager.ProcessCommand(request.Command);
           }).ConfigureAwait(false);
       }
       return new SlashCommandResult(
           Command: request.Command,
           Success: true,
           Status: "command_sent",
           SummaryText: $"命令已发送: {request.Command}");
   }
   catch (Exception ex)
   {
       return new SlashCommandResult(
           Command: request.Command,
           Success: false,
           Status: "command_sent",
           SummaryText: $"命令已发送但执行异常: {ex.Message}");
   }
   ```
3. 异常处理：ProcessCommand 抛异常时仍返回 command_sent（fire-and-forget 模式下无法确定命令是否执行），但将异常信息放入 SummaryText 供调试

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AI 客户端 → CLI MCP 协议 | 不可信输入——AI 模型可能生成格式错误的命令（不含 / 前缀、超长、含特殊字符） |
| CLI → 命名管道 → Plugin | 可信（经过操作协议调度器路由，类型安全的 Request） |
| Plugin → ICommandManager.ProcessCommand() | 已通过输入验证（D-01/D-02），但命令字符串内容不受限 |
| ICommandManager → 游戏/Dalamud 内部 | 不可控——ProcessCommand 可能抛异常，异常被 try-catch 捕获不应崩溃整个操作 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-01 | Tampering | SlashCommandOperation.ExecuteAsync | mitigate | 输入验证（D-01/D-02）：命令不必以 / 开头或超 256 字符→返回 validation_failed。ICommandManager 自然过滤无效命令（D-02 策略） |
| T-13-02 | Denial of Service | SlashCommandOperation.ExecuteAsync | mitigate | 256 字符长度上限（D-01）防止超大输入；ProcessCommand 在 Framework 线程同步执行，每次 MCP 调用一个命令，无并发放大风险 |
| T-13-03 | Spoofing | CLI MCP → Plugin | accept | MCP 协议层不做身份验证（项目设计决定），攻击者需本地命名管道访问权限。本地攻击者已有多年前提，MCP 暴露控制由 `enableUnsafeOperations` UI 开关管理 |
| T-13-04 | Elevation of Privilege | PluginOperationExposurePolicy | mitigate | `command.slash` 归入 UnsafeOperationIds，受 UI `enableUnsafeOperations` 开关控制。默认关闭，仅用户主动可用 |
| T-13-05 | Information Disclosure | SlashCommandResult.SummaryText | accept | SummaryText 包含命令原文和异常消息——MCP 协议设计为发送结构化摘要给 AI 客户端。工具描述中注明游戏原生命令不可用，不暴露游戏内敏感数据 |
| T-13-06 | Repudiation | command.slash 操作日志 | accept | MCP/CLI 调用不记录审计日志（项目范围内决策）。Phase 10 的日志读取能力可事后追溯，但不适用于实时审计 |
</threat_model>
